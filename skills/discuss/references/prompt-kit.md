# 喂给子 agent 的 prompt 怎么组装

> **机器执行版在 `../protocol/moderator.md` 的「prompt 怎么组装」一节**——那份是
> moderator 每轮真正执行的契约,改动以那边为准并同步 `scripts/plan_check.py`
> 的断言;本文件是给人读的展开说明与实测理由。

子进程无状态,每次调用都要把需要的上下文完整塞进去。

## 骨架

```
你是 <agent 名>,正在参加一场技术讨论。

【你的站位】
<整场不变,来自名册>

【已确立的前提】
- <前提 1>(Claude 提出,第 2 轮,无人反对)
- <前提 2>(用户确认)

【已废弃的方向 —— 不要再论证】
- <方向 X>(用户第 6 轮改的主意)

【未决问题】
1. <问题 1>
2. <问题 2>

【讨论记录】
<按下面的裁剪规则组装,带署名>

【这一轮请你回答】
<一个具体问题,或用户 @ 你的原话>

回答完在最后附上:
立场:<一句话>
同意:<你接受对方哪几点>
不同意:<具体哪一点 + 为什么,指名道姓说是谁的哪句话>
如果我错了:<一句可验证的条件>
```

## 裁剪规则

- **最近两轮:全文**,带署名
- **更早的回合:每人只留一行立场**
- transcript 只增不改;方向变更插一行分隔符,不删旧内容

```
[用户]   那计费周期用自然月还是订阅日?
[Claude] 我倾向订阅日,理由是……
[codex]  我不同意 Claude 的第二点,因为……
── 方向变更:自建计费 → Stripe(用户,第 6 轮)──
[用户]   算了,直接上 Stripe
```

**署名是关键**,不是格式洁癖。实测:带署名的记录能产生指向性反驳(「我不同意 Claude 说的 X」),不带署名就变成各说各话。这是"三份独立 review"变成"讨论"的唯一开关。

## footer 契约

四个字段,不多不少:

```
立场:<一句话>
同意:<接受对方哪几点,没有就写"暂无">
不同意:<具体哪一点 + 为什么,指名道姓>
如果我错了:<一句可验证的条件>
```

- 「不同意」必须**指名道姓**说是谁的哪句话,否则退化成泛泛而谈
- 「如果我错了」是**反伪共识的抓手**——写不出自证伪条件的一致,不算数。不能省

## 用户 @ 某人时

用户原话**原样**放进「这一轮请你回答」,署名 `[用户]`。不转述、不软化、不补理由。

追加一句要求:「先直接回应用户这句质疑(接受还是不接受、为什么),再补别的。不要绕回你上一轮的立场重述。」

用户话里若有事实错误,在 Claude 自己那段发言里指出,**转达给 agent 的那份不动**。

## 中途加人的入场简报

新人拿到的是**共识状态头 + 最近两轮全文**,不是全量 transcript。两个理由:它没参与前面的辩论,喂全量既贵又让它假装在场;更重要的是**中途加人的价值就是没被前面锚定**,喂太多历史反而毁掉它。

简报末尾必须带:

```
你是第 <N> 轮加入的,上面是前面讨论的摘要。
如果你觉得已确立的前提有问题,直接说 —— 不要因为它们已经写在那里就默认接受。
```

少了这句,新人会默认接受前提、退化成附和。

## 显式对赌

- **必须给不同任务**。给两个 agent 同一个问题不叫对赌,叫重复采样,只会拿回两份差不多的通用建议
- **首轮不给对方历史**(blind opening),避免先发言者锚定后发言者
- 一方缺席则对赌无效,问用户重试还是改单人回答

## 渲染回用户

```
**codex** · 8.2s
先别争全量还是窗口,这可能解错了问题。你们两个方案都假设……

  立场:先确认写放大来自哪一层,再选方案
  不同意:Claude 说「窗口足够」—— 前提是写入均匀,日志类负载不是
  如果我错了:写入其实是均匀的,那窗口确实够
```

失败一行,不展开 stack trace:

```
**gemini** · 调用失败(未认证)· 本轮缺席
```

回合末尾状态行:

```
─── 讨论模式 · codex + gemini · 第 4 轮 · 未决 2 ───
```
