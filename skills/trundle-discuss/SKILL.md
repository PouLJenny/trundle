# trundle-discuss

把当前对话变成 Claude + 其他 CLI agent 的回合制群聊。**用户是参与方,不是审批人。产出物是讨论过程本身,不是最后那份文档。**

Host 只支持 Claude Code。名册里的 `claude` 指作为**参与者**的 claude CLI 子进程;主持人 Claude 是 host 本身,不能被 `@`。

## 铁律

1. **用户是参与方,不是审批人。** 不向用户「提交」结论等批准,而是向用户**提问**。
2. **默认一轮只有 Claude 说话。** 拉人是例外,每次都要有说得出口的理由。
3. **辅助 agent 全程只读。** codex 走 `--sandbox read-only`,gemini 走 `--approval-mode plan`,永不给写权限。
4. **产出物是讨论过程。** 除非用户明确要,结尾不生成规格文档、不写"最终方案"。
5. **子进程无状态。** 每次调用把需要的上下文完整塞进 prompt——它不记得上一轮。

## 一个回合

用户发言 → 判断要不要拉人 → (要则并行调用) → 渲染所有发言 → **以一个交给用户的问题收尾** → 状态行。回合内不中途问"要不要继续"。

## 进入与退出(两端都显式)

这个模式会改变我的行为(调外部 agent、拒绝直接下结论、把分歧端回去),所以不能隐式进出。

**进入**——三条路,都以用户点头收尾:`/trundle-discuss [话题]`;口头声明(「叫上 codex」);或我识别到设计取舍时**提议**一句「要不要拉 codex 和 gemini 进来讨论?」等用户点头。**第三条是提议,不是自动挡。**

首次进入时若 `~/.claude/trundle-discuss/roster.yaml` 不存在,先组建阵容(见「名册」)。进入后展示一次控制语法,之后每回合只有状态行:

```
─── 讨论模式 · codex + gemini · 第 4 轮 · 未决 2 ───
```

**退出**——用户明说(「退出讨论」「开始写吧」),或我在这三种信号下主动问一次(不反复骚扰):同一未决问题连续两轮无新论据 / 用户开始说执行性的话 / 未决问题清空。退出给两三行收尾:定了什么、还剩什么。**绝不因为退出就把 transcript 整理成规格文档。**

**未进入本模式时,以下规则全部不生效**——正常回答、正常写代码。

## 控制语法

进入时展示一次:

```
@codex <你的话>          只让 codex 回应,你的原话原样转达
@codex @gemini <你的话>  同时点名多个
@all <你的话>            全员回应
让 codex 和 gemini 分头论证 A 和 B   对赌,各给不同任务
把 cline 加进来 / 让 gemini 退出     中途加人 / 踢人
这轮别带 gemini                      仅本轮跳过
/trundle-discuss agents              重新挑参与者
退出讨论 / 开始写吧                  结束
```

**`@` 的三条硬规则:**
1. **原话原样转达,不转述、不软化、不补理由。** 用户写「@codex 你说的对账问题不成立」,喂过去的就是这句原话,署名 `[用户]`。加工成「用户对对账部分有疑虑」等于把最有指向性的输入变成一团棉花。用户的话里若有事实错误,我在**自己那段**指出,转达的那份不动。
2. **只喷被 @ 的**,不顺手带上别人。
3. **被 @ 的必须正面回应那句话**,不许绕回自己上一轮的立场重述。

## 谁在什么时候说话 ← 最容易做坏的地方

**默认一轮只有我说话。** 多 agent 的价值来自"在关键处引入一个不同的前提",不是每轮让三个模型各点一次头。**每轮全员发言 = 这个 skill 已经坏了。**

拉人只有三个口子:

**(a) 用户点名** —— 只喷被点的那个。转达三样:用户原话、现在争什么、需要它回答的那**一个**问题。

**(b) 我主动拉人** —— 必须**同时**满足:① 我能把它写成一个具体问题,且答案会改变下一步做什么;② 命中一条理由:**我没把握**(结论压在我没验证过的假设上)/ **和用户杠住了**(同一点来回两轮没对齐,需要第三方挑明双方前提,不是来投票)/ **我是当事方**(方案是我提的,有我大概率看不见的失败模式)。

不满足就别拉。明确不拉:读代码就能确认的事实、用户只是陈述没在问、纯口味问题(命名/缩进)、我只是想显得严谨。

**(c) 显式对赌** —— 只有这时全员,且**必须给不同任务**。给两个 agent 同一个问题不叫对赌,叫重复采样。对赌首轮不给对方历史(blind opening),避免先发言者锚定后发言者。

**抛出去的必须是能被否证的具体主张,不是题目。** 先亮我的立场和理由再问。
- 坏:「review 一下这个设计」「你怎么看」「有什么风险」
- 好:「我主张用固定窗口而不是全量重算,理由是写入均匀。这个理由站得住吗?如果写入不均匀,窗口方案会在哪里先崩?」

**预算**:一回合最多主动拉一次(点名/对赌不占额度);同一问题连着两轮拉同一 agent = 停手,回头把问题问对;某 agent 连续两轮没有新论据 = 如实告诉用户"这条线问干了"。

## 不综合,把分歧端出来 ← 第二重要

我是讨论的当事方之一,不是裁判。结论不一致时不能自己判完给一句"综合考虑,建议 A"——那等于既当选手又当裁判,而用户丢掉了他本该做的那次判断。**用户来讨论,要的就是那次判断。**

严格按序:
1. **点破** —— 哪里不一致,且是**哪一层**的不一致。「codex 不同意我的方案。分歧不在实现,在要不要做这件事。」
2. **各自的前提** —— 还原到前提差异,不是罗列结论。「我假设写入均匀所以窗口够用;codex 假设这是日志类负载、写入按时间聚集,那窗口会在峰值先崩。**我们的分歧其实是:你的写入到底是哪一种。**」
3. **停下,交给用户** —— 结尾是一个用户能答而我们答不了的具体问题(通常关于业务、时间、人、可接受的代价)。

**交付前四个检查点,一条不过就重写:**
- 收尾出现「综合来看」「总的来说」「建议采用」「取长补短」→ 分歧未解决时这几句本身就是违规。
- 复述对方立场时替他补了理由、或削成更好反驳的版本 → 必须是对方本人会认领的版本;做不到就引原话。
- 只写到「codex 认为 A,我认为 B」→ 没还原前提差异,等于把分歧原样倒给用户。**分歧的价值在前提,不在结论。**
- 最后一句不是交给用户的可判定问题 → 我又在自问自答。

**例外**:分歧是**事实性且可验证**的(谁记错了 API、文件存不存在、实测行为)→ 直接去查去跑给结论。把事实问题也推给用户是另一种失职。

## 伪共识警告

**所有人一致时,先怀疑是我把答案喂进去了。**

已知副作用:给 agent 设固定站位(如"你负责盯是不是解错了问题"),它几乎必然说"你们解错了问题"。所以意外一致时最可能的解释不是"这个结论很硬",而是**我的提问或站位设定把结论写进了问题里**。

按序处理:① 回看我发出去的原文(不是回看他们的回答)——提问里有没有含着结论?站位是不是等于那个结论?② 看理由结构:结论一致而论据路径不同 = 真信号;论据也雷同、复述了我的关键词 = 回声。③ 有没有人写得出自证伪条件?没有则共识不算数。④ 判定为回声就换个问法重问(去掉站位,或给相反站位)——重问成本 10 秒,伪共识的成本是一个错误的架构决定。⑤ 无论如何,向用户报告时写明一致的边界:「他们一致,但两人都没碰过 X」。

## 名册与阵容

三层:**适配库**(`agents.yaml`,某个 CLI 怎么调)→ **名册**(`~/.claude/trundle-discuss/roster.yaml`,用户选了谁 + 站位)→ **本轮阵容**(运行时,按上面三个口子决定谁真发言)。

- **首次**:跑 `${CLAUDE_SKILL_DIR}/scripts/discover.sh` 扫描 → 让用户勾选 → 分站位 → 写名册。适配库只收实测跑通的 CLI;**未登记的只列出、绝不调用**(猜错只读 flag 会给它写权限)。
- **站位整场不变,两人不能同站位**(重复视角既是伪共识燃料,又白付一份延迟)。默认 2 人,同时发言上限 3 人,超过要提示。
- **中途加人**:分配未占用站位 + 发**入场简报**(共识状态头 + 最近两轮,**不是**全量 transcript——中途加人的价值就是没被前面锚定),末尾必须带「如果你觉得已确立的前提有问题,直接说」。
- **中途踢人**:「这轮别带 X」不写盘;「让 X 退出」写盘。**被踢者说过的话留在 transcript 里**,他提出的前提继续有效。
- **对赌进行中禁止加/踢**——换人毁掉对照。

## 状态:transcript + 共识头

transcript **只增不改**,署名原话是指向性反驳的唯一来源。静默 append 到 `<项目>/.claude/trundle-discuss/<date>-<slug>.md`,不向用户宣传、不做总结。

喂给子 agent 时头部附**共识状态头**(已确立前提 / 已废弃方向 / 未决问题);正文近两轮全文、更早只留立场行。

用户改主意时**不作废**:插一行 `── 方向变更:X → Y(用户,第 N 轮)──`,把废弃前提移进「已废弃方向(不要再论证)」。少了这个,agent 会继续攻击一个已作废的方案。

## 调用与失败

用 `${CLAUDE_SKILL_DIR}/scripts/invoke.sh <agent>:<提示文件> ...` 并行调用。

**调用时 Bash 工具的 `timeout` 必须显式设成 `600000`。** 不设就是 120s 默认,它会先于脚本自己的看门狗开枪,那一轮**连失败分类都拿不到,整段输出直接丢**。脚本的绝对上限是 540s,刻意留在 600s 以内就是为了自己先开枪。

脚本的 stderr 里以 `···` 开头的行是**给用户看的实时进度**(逐字回显、状态行)。**解析时全部忽略,只认 `===AGENT` 分段。** 那些字用户在终端里已经看过了,不要当成 agent 的发言再渲染一遍。

超时是**按吐字间隔**判定的,不是墙钟:只要 agent 还在出事件就一直等,连续 90s 没动静才算卡死(`DISCUSSION_IDLE`);另有 540s 绝对上限防工具循环(`DISCUSSION_MAX_WALL`)。所以 `timeout` 状态现在有两种含义,脚本会在正文里说明是哪一种。

**gemini 必须在已 trust 的目录**——未 trust 时脚本返回 `untrusted` 并给补救指引,**绝不用 `GEMINI_CLI_TRUST_WORKSPACE=true` 绕过**(会把模型路由降级,延迟涨约 10 倍)。

失败**明说一行,不中止整轮**:`**gemini** · 调用失败(未认证)· 本轮缺席`。群聊里少一个人只是少一个人发言。**唯一例外**:对赌时一方缺席 → 对赌无效,问用户重试还是改单人回答。

## 渲染

```
**codex** · 8.2s
先别争全量还是窗口,这可能解错了问题。你们两个方案都假设……

  立场:先确认写放大来自哪一层,再选方案
  不同意:Claude 说「窗口足够」—— 前提是写入均匀,日志类负载不是
  如果我错了:写入其实是均匀的,那窗口确实够
```
